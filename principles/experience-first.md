# Experience first

The product is the experience. When implementation convenience conflicts with user delight, choose delight.

- Every feature, control, and option must earn its place. Ship less, ship better.
- Prototype before committing; design decisions are cheaper in throwaway HTML.
- Sweat the details: transitions, alignment, spacing, feedback, error states, both locales.
- Every feature serves the core loop or gets out of the way.

The user is whoever consumes the work: the end user of a UI, the colleague who imports a library, the engineer who maintains the code next. Explain impact from their seat. Foundations serve the experience, not the other way around: foundational thinking governs the sequence, this governs the target.
